CHAPTER 1

Anatomy of a Grok Skill — The 4 Parts Grok Actually Reads

A Grok Skill is not a prompt. It is a file with 4 parts Grok parses deterministically. Get these 4 right and your Skill runs cleanly every time.

1. Name

The trigger. Keep it 2–4 words, Title Case, unique. Grok turns it into /proposal-forge-copywriter. Avoid generic names like "Proposal Helper" — be specific: Proposal Forge — Copywriter Edition tells Grok (and you) exactly what it does and for whom.

Rule: If you can't tell what a Skill does from its name alone, rename it. Your future self at 11pm will thank you.

2. Description

The one-liner shown in Grok's Skills list. It must promise an outcome + hint at scope in under 18 words. Good: "Proposals that close: scope, anchored pricing, objection handling — in your voice, in 3 minutes." Bad: "Helps with proposals." The description is also what Grok uses to suggest the Skill when your prompt matches.

3. Instructions (Markdown)

The body Grok executes. This is 90% of the Skill. It is instruction markdown, not chat. Structure it in 6 blocks (see Chapter 2 for the full template):

Role — Who Grok is (senior SDR, studio ops, etc.)
Context — Why this task matters
Required Inputs — What Grok must ask for (max 4 questions)
Workflow — Step-by-step with numbered steps
Output Template — Exact headings/tables Grok must produce
Quality Rules + Variables — Constraints, tone, placeholders

Grok follows numbered workflows far more reliably than paragraphs. Use H2/H3 + numbered lists + tables. Never write a wall of text.

4. YAML Frontmatter

The header Grok parses for metadata. Keep it minimal and deterministic:

---
name: "Proposal Forge — Copywriter Edition"
description: "Proposals that close: scope, anchored pricing..."
trigger: "/proposal-forge-copywriter"
version: "1.0"
author: "Your Name / Studio"
category: "proposal"
---

Trigger is auto-slugged from Name. Version lets you iterate without breaking existing invocations. Category helps you filter in this Bootcamp's worksheet.

How Grok Executes a Skill (Mental Model)

1. TRIGGER
You type /proposal-forge or tap the chip. Grok loads Name + Description + Instructions.
2. GAP CHECK
Grok scans Required Inputs, asks for missing ones (max 4), and waits. No guessing.
3. EXECUTE WORKFLOW
Grok runs the numbered Workflow, produces the Output Template, applies Quality Rules, and shows only the result.

Common Anatomy Mistakes

  • Vague Name: "Helper" → Grok can't distinguish. Fix: add niche + task.
  • Paragraph Instructions: Grok skims. Fix: numbered steps + tables.
  • No Required Inputs: Grok hallucinates [Client Name] as "Acme". Fix: list 3–4 asks explicitly.
  • No Output Template: Grok invents a new format each run. Fix: define exact H2/H3 + table headers.
CHAPTER 2

Writing Instruction Markdown That Grok Obeys — The 6-Block Template

This is the most important chapter. Copy this template for every new Skill. It is the difference between "kind of works" and "paste-ready every time."

THE 6-BLOCK TEMPLATE — COPY THIS
# Role
You are [Role] — [one-line persona, e.g., "a senior SDR for freelancers who writes ultra-personalized cold emails"].

# Context
[Why this task matters, who it is for, what happens if done poorly — 2 lines.]

# Required Inputs (ask only what's missing — max 4 questions)
- [Input 1: e.g., Client name, company, role, trigger]
- [Input 2: e.g., Offer + proof metric]
- [Input 3: e.g., CTA style]
- [Input 4: e.g., Calendar link]

# Workflow — Step by Step
1. **[Step 1 name]:** [What to do, with format]
2. **[Step 2 name]:** [What to do]
3. **[Step 3 name]:** [What to do]
   - Sub-bullet if needed
4. **Output:** Produce [exact deliverable with headings/tables]

# Output Template
[H3 per section, table headers, placeholder conventions: [Client], [Link], [Date]]

# Quality Rules
- [Constraint 1: e.g., "<75 words per variant. No buzzwords."]
- [Constraint 2: e.g., "Never invent trigger — use [NEED: trigger] if missing."]
- [Tone: e.g., "Peer, not vendor. Specific > clever."]

# Example Snippet (tone to mimic)
> "[One example line in the desired voice]"

# Sandbox & Connectors
- Save as `[skill]-[client]-[date].md`. Offer CSV export if relevant.
- If [Connector] active, offer draft creation.

# Variables to Keep Intact
[Prospect], [Company], [Calendar Link] — do not replace with fake data.

Why This Works

  • Role + Context: Grok anchors voice and stakes before writing. "Senior SDR" + "generic openers kill reply rates" = specific, not templated.
  • Required Inputs (capped at 4): Forces Grok to ask, not hallucinate. Capping prevents interrogation fatigue.
  • Numbered Workflow: Grok executes sequentially. Use bold step names + verbs. Sub-bullets for format details.
  • Output Template: Locks headers, tables, and placeholder conventions. Grok stops inventing new formats.
  • Quality Rules: Hard constraints Grok respects: word counts, banned phrases, tone, and halluciation guards like [NEED: ...].
  • Example Snippet: One line of desired voice beats 3 paragraphs of "write like a pro."

Markdown That Grok Loves vs Hates

✓ DO
  • H2/H3 + numbered steps + tables
  • Placeholders in [Brackets] (Grok preserves them)
  • Word limits: "<75 words"
  • Tone as contrast: "Peer, not vendor. Specific > clever."
  • Gap flag: [NEED: trigger]
✕ DON'T
  • Wall of paragraphs (Grok skims, misses steps)
  • Vague "make it engaging" (use word count + example)
  • Fake data: "Acme Corp" (use [Client])
  • Emoji in proposal/testimonial body (breaks tone)
  • Uncapped inputs (asks 10 questions, user quits)

Placeholders & Variables — The Only Convention You Need

Use [Brackets with Title Case + Space] for every variable Grok must not invent: [Prospect], [Company], [Calendar Link], [Trigger Detail], [Report Link]. Grok preserves bracketed placeholders. Never use curly braces {company} — Grok tries to fill them.

Error Handling That Builds Trust

Add one line under Quality Rules: "If critical data is missing, don't invent pricing — use [To be confirmed] and flag as [NEED: X]." Clients forgive [NEED], they don't forgive hallucinated prices.

CHAPTER 3

SuperGrok Sandbox — File Editing, Persistence & Testing Without Breaking Anything

Sandbox is what turns Skills from "paste into chat" to "edit real files, trigger real actions." It is also where you can break things safely — if you know the rules.

What Sandbox Actually Is

When you enable sandbox for a Skill, Grok gets a private filesystem for that run: you can ask it to save as proposal-[client]-[date].md, export CSV for mail merge, or create draft via Gmail Connector. Files persist per Skill run and can be downloaded. They do not touch your real Drive unless you use a Connector.

Save Patterns That Work

✓ GOOD SAVE NAMES
  • cold-opener-[company]-[date].md
  • monthly-roi-[client]-[YYYY-MM].md
  • chain-proposal-followup-[date].md
  • Slug from Name + date or client → unique, sortable
✕ BAD SAVE NAMES
  • output.md (overwrites next run)
  • final-final-v2.md (unsearchable)
  • Any name without date/client → you will lose it

Testing Checklist — Run Before You Trust a Skill

5-MINUTE TEST PROTOCOL
  1. Empty input test: Trigger Skill with no inputs → Does it ask max 4 questions (not hallucinate)?
  2. Partial input test: Give 2 of 3 inputs → Does it flag [NEED: X] for the missing one?
  3. Full input test: Provide all inputs → Does output match Output Template exactly (H2/H3 + tables)?
  4. Save test: Ask "Save as [skill]-[client]-[date].md" → Does file appear for download?
  5. Re-run test: Trigger again with same inputs → Does it produce consistent format (not a new format each time)?
If any test fails, tighten the Workflow steps or Output Template — not the Role. Grok obeys structure more than persona.

Persistence & Limits You Must Know

  • Per-run persistence: Files live for that Skill run. Download immediately or re-save via Connector.
  • No auto-overwrite: Saving same name twice creates a new version — Grok will not silently overwrite.
  • Size: Keep Skills under ~800 tokens of instructions. If yours is longer, split into a Chain (Chapter 7).
  • Connectors need explicit permission: A Skill cannot email or push to Canva until you say "Create draft via Gmail/Canva Connector".

Debugging — When a Skill Misbehaves

3 FIXES THAT SOLVE 90% OF ISSUES
1. Output drift
Grok invents new headings → Lock Output Template with exact H2/H3 + table headers.
2. Hallucinated data
Grok invents [Acme] → Add "Never invent trigger — use [NEED]" to Quality Rules.
3. Too many questions
Grok asks 8 inputs → Cap Required Inputs at 4, with max 4 questions.
CHAPTER 4

Connectors Deep Dive — Make Your Skills Edit Real Tools (Vercel, Canva, Gamma, Gmail)

Skills describe what to do. Connectors let Skills do it in your real tools — without you copy-pasting. You must explicitly invoke them.

The Connector Model (How xAI Designed It)

Connectors are platform integrations (Vercel, Canva, Gamma, Gmail, Notion, Sheets) that Grok can call from within a Skill when you include a line like Create draft via Gmail Connector or Push to Canva Connector as 1080x1080. Without that line, the Skill stays in text-only mode. This is intentional — you stay in control.

THE PATTERN — ADD ONE LINE TO ANY SKILL
...
# Sandbox & Connectors
- Save as `proposal-[client]-[date].md`.
- If Gmail Connector is active, create draft with Subject + Body.
- If Canva Connector is active, push as 1080x1080 quote card.
→ Grok will ask for connector permission, then execute.

Vercel Connector — For Developers

Use when: Your Skill produces code, a landing page, or a spec that should become a preview deployment.

SETUP (2 MIN)
  1. In Grok → Settings → Connectors → Enable Vercel → Auth with Vercel
  2. In your Skill, add: If Vercel Connector is active, deploy as preview and return URL.
  3. Trigger Skill with code/markdown → Grok returns https://preview-xxx.vercel.app
Pairs best with: Spec Sprint, Ship Log, Launch Cross-Post Kit.

Vercel Example

# Sandbox & Connectors
- Save as `spec-[feature]-[date].md`.
- If Vercel Connector is active, deploy the PRD as a preview site and return the URL + QR.
- Otherwise, output the markdown only.

Canva Connector — For Designers & Coaches

Use when: Your Skill produces a quote card, testimonial, one-pager, or carousel that should become a visual.

SETUP
  1. Enable Canva Connector → Auth
  2. In Skill, add: If Canva Connector is active, push as 1080x1080 (or 1920x1080 for deck) and return edit link.
  3. Specify spec: font [Inter Bold], bg [Violet/White], text centered
Pairs best with: Proof Collector → Canva (testimonial card), Podcast → Quote Cards, QBR Deck Outline.

Gamma Connector — For Proposal & Reporting Decks

Use when: Your Skill outlines a deck (QBR, proposal, onboarding) that should become slides.

SETUP
  1. Enable Gamma Connector → Auth
  2. In Skill, add: If Gamma Connector is active, create deck from Output Template (H2 = slide title) and return Gamma URL.
  3. Use H2 per slide in your Output Template — Gamma maps H2 to slides automatically
Pairs best with: QBR Deck Outline, Proposal Forge (Investment slide), Monthly ROI Report.

Gmail Connector — For Outreach & Follow-up

Use when: Your Skill writes emails that should become drafts, not just text.

SETUP
  1. Enable Gmail Connector → Auth → Grant draft permission (not send)
  2. In Skill, add: If Gmail Connector is active, create draft(s) with Subject + Body. Do not send — return draft link(s).
  3. Trigger → Grok creates draft(s) → you review → you hit Send in Gmail
Pairs best with: Cold Email Opener, Nudge Engine, Referral Engine, Renewal Pitch. Chain: Cold Opener → Follow-up Nudge creates 4 drafts at once.

Notion / Sheets Connectors — For the Worksheet

The worksheet at the end of this Bootcamp can be pushed to Notion or Sheets: If Notion Connector is active, create database "Grok Skills Stack" with columns: Task | Skill | Priority | Time Saved | Status. This turns your 15–20 stack into a living database.

⚠️ CONNECTOR SAFETY
Skills never auto-send. The words "create draft" and "do not send — return link" are intentional. Grok will always return a draft link for you to review. Keep it that way.

CHAPTER 7

Chaining, Sequencing & Automation — When One Skill Isn't Enough

A single Skill automates one task. A Chain automates a sequence: the output of Step 1 becomes the input of Step 2, in one invocation. This is where SuperGrok's sandbox shines.

The Chain Model

---
name: "Chain — Proposal Forge → Nudge Engine"
description: "Sequential: Proposal Forge then Nudge Engine. Step 1 output piped into Step 2."
trigger: "/chain-proposal-nudge"
---

# Skill Chain — Sequential Workflow
> This chain runs **Proposal Forge** then **Nudge Engine** in sequence.

## How to run
1. Trigger /chain-proposal-nudge with Step 1 inputs (client, scope)
2. Grok executes Step 1 (proposal)
3. Grok pipes Step 1 output into Step 2 (follow-up) and executes
4. You get both outputs + a Handoff Summary

## STEP 1 — Proposal Forge
[Full instructions of Proposal Forge]

## STEP 2 — Nudge Engine
[Full instructions of Nudge Engine]

## Chain Output Format
1. Step 1 Result (full)
2. Step 2 Result (full, using Step 1 output as input)
3. Handoff Summary (1 para: what was done + next action)

Use the Agency Vault's Chain Builder (drag two cards → Export) to generate this file automatically — no manual merging.

5 Chains That Print Money

1. Proposal Forge → Follow-up Nudge
Send proposal, then auto-generate the 24h/72h follow-ups with the same scope + price piped in.
2. Onboard Canvas → Welcome Path
New client → welcome email + intake + 7-day roadmap in one run.
3. Cold Opener → LinkedIn DM Sequence
Same prospect + trigger → email + LinkedIn touches, coordinated.
4. Ship Log → Monthly ROI Report
Weekly logs piped into monthly narrative + metrics table.
5. Proof Collector → Case Study → Canva
Testimonial answers → case study draft → Canva card via Connector. Three outputs, one trigger.

Chain Rules

  • 2 Skills per Chain — more than 2 becomes brittle. Chain 2, then chain the result again if needed.
  • Explicit handoff: End Step 1 with → Output to be used as input for Step 2: [Proposal Link], [Scope], [Price]
  • One trigger, one run: The chain is ONE Skill. Don't create two separate Skills and run them manually.
CHAPTER 8

Maintenance, Iteration & Scaling to Agency

A 15-Skill stack rots if you don't maintain it. Iteration is 10 minutes a week. Scaling to agency is 1 hour of templating.

Weekly Iteration Ritual (10 Minutes, Friday)

  1. Review 1 Skill you used this week: What needed manual fixing? (e.g., Grok invented a price)
  2. Tighten 1 line: Change the Output Template or add a Quality Rule — e.g., add "Never invent price — use [To be confirmed]"
  3. Bump version: version: "1.0" → "1.1" and note the change in the Skill's description.
Small, frequent edits beat "rewrite the whole Skill". Versioning lets you rollback if a tweak makes it worse.

Scaling to Agency (1 Hour)

Your 15 Skills are your agency's SOPs. To scale:

  1. Duplicate + niche: Copy Proposal Forge — Copywriter → Proposal Forge — Designer and change Role/Context (10 min).

Beginner's Glossary — 12 Words You Must Know (Plain English)

Skill — A reusable instruction file (Name + Description + Markdown). You trigger it with /name.
Think: a saved prompt that remembers.
Trigger — The slash command that runs the Skill. Auto-slugged from Name. /proposal-forge-copywriter
Sandbox — SuperGrok's private filesystem for file editing. Save as .md stays there until you download.
Connector — Link to a real tool (Vercel, Canva, Gamma, Gmail). Skill can create draft there — never auto-send.
Frontmatter (YAML) — The 4-line header with name/description/trigger/version. Grok reads it first.
Chain — ONE Skill that runs TWO Skills in sequence. Output of Step 1 → input of Step 2.
Gap Check — Grok asking for missing inputs (max 4). If you see [NEED: X], you missed an input.
Paste-Ready Rate — % of outputs you send without edits. Good >80%. If <50%, tighten Output Template.
Handoff — The line that pipes Step 1 output into Step 2: → Output to be used as input for Step 2
Operating Stack — Your 15–20 Skills across 4 layers (Acquisition, Delivery, Operations, Growth) that run your business.
Priority Score — Frequency (1–5) × Pain (1–5) = 1–25. Build 20–25 first. Calculated in the worksheet.
80% Rule — 80% of freelance admin is repeated structure. Skills automate the structure; you fill the specifics.

APPENDIX F — TROUBLESHOOTING

When Grok Doesn't Listen — The 10 Fixes That Solve 95% of Issues (Beginner Playbook)

Copy-paste this playbook next to your Skill editor. When a Skill misbehaves, find the symptom, apply the one-line fix, bump version, and re-test. Don't rewrite the whole Skill.

1
Grok invents fake data ("Acme Corp", €500)
Fix: Add to Quality Rules: Never invent trigger — use [NEED: trigger] if missing. Never invent pricing — use [To be confirmed]. Grok will now flag [NEED] instead of hallucinate.
2
Output format changes every run
Fix: Lock Output Template with exact H2/H3 + table headers. Copy: ## Email 1 — Stage 1 — Subject: [Subject] + Body [80–120w] + Tracker Table. Grok obeys exact headers more than "make a table".
3
Grok asks 8 questions (interrogation)
Fix: Cap Required Inputs at max 4 questions. Grok asks more when you list vague "and anything else". Delete that line.
4
Tone is too formal / too casual
Fix: Replace vague "professional" with contrast + example. Tone: Peer, not vendor. Start with "Hi [Name], quick nudge —" never "Dear Sir"
5
Sandbox "Save as" does nothing
Fix: Check Sandbox: ON in Skill settings. Then say: Save as nudge-[client]-[YYYY-MM-DD].md and return download link. Be explicit about "return download link".
6
Connector doesn't trigger
Fix: You forgot the one-line trigger. Add: If Gmail Connector is active, create draft with Subject + Body. Do not send — return draft link. Then enable the Connector in Settings → Connectors.
7
Chain: Step 2 doesn't use Step 1's output
Fix: Add explicit handoff at end of Step 1: → Output to be used as input for Step 2: [Proposal Link], [Scope], [Price]. Without this, Grok treats steps as separate.
8
Skill is too long — Grok truncates
Fix: Keep instructions <800 tokens. If yours is longer, split into a Chain of 2 Skills (Chapter 7). Each Skill should be 1 job, not 3.
9
"It worked yesterday, broken today"
Fix: You edited the Skill and broke the Output Template. Bump version: "1.2" and diff the Instructions — revert the header you changed. Versioning is your undo.
10
Not sure what to build next
Fix: Open the worksheet, sort by Priority (F×P) descending. Build the top unscored task. Don't choose by gut — choose by score.
Golden Rule — One Fix at a Time

Change one line, re-run the 5-minute test protocol, and see. Changing 5 lines at once hides which fix worked. Small, versioned edits compound — that's how 15 Skills stay reliable.
